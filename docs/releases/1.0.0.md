# Talos CLI 1.0.0

Major: the TUI system prompt now composes its behaviour discipline from one of two selectable doctrines, and the
choice belongs to the Session rather than to live configuration.

## Changes

- `/doctrine` selects the behaviour doctrine: a long-form discipline set covering task scope, executing actions with care, tool use, tone, and output efficiency, or a minimal set made of one identity line and a short guidelines list. The default is the long-form set.
- The doctrine is stored on the Session once it exists. A later configuration edit seeds new Sessions only, so it cannot change how a conversation in progress behaves.
- The doctrine is fixed to the Session once its first user message is sent. Before that, `/doctrine` may still change it; afterwards the Runtime rejects the change with `409 local_prompt_doctrine_locked` and the TUI reports that rejection instead of retrying.
- A child Session inherits its parent's doctrine, and a fork copies its source's, so a delegated or branched conversation keeps the discipline that shaped it.
- The doctrine in force is a permanent status-line item (`Apocalypse` / `Stargate`, compacted to `APOC` / `STAR`), and `/doctrine status` reports it.
- The discipline is its own composition layer. Identity, runtime facts, permission wording, memory, response style, and tool rules stay Talos-owned, so switching doctrine changes only the discipline.
- The TUI system prompt no longer repeats rules the runtime already injects, and it states continuity ownership as a guarded runtime rule rather than a role narrative, so a delegated child render never claims to own the conversation.
- Classic remains the default skin.
