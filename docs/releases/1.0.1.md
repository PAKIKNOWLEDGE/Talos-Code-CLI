# Talos CLI 1.0.1

Patch: the behaviour doctrine can now be chosen before the Session exists, so the choice that anchors a conversation is made
before the first message rather than after it.

## Changes

- `/doctrine` is available in an empty chat. Running it without arguments opens a picker for `apocalypse` or `stargate`, and the chosen value is carried into `createSession` so the Session is created with that doctrine already stamped. No intermediate Session is created and corrected afterwards.
- The status line shows the pending choice immediately, so the decision is visible before the chat starts, and `/doctrine status` reports the pending value or `not chosen yet`.
- Once a Session has a user message the doctrine is anchored and the runtime still rejects changes with `409 local_prompt_doctrine_locked`. In that state `/doctrine` with no arguments reports the anchored doctrine instead of offering a selection that would be refused, and the rejection message names the anchored value instead of suggesting a new Session.
- The runtime rejection text now reads `The behaviour doctrine is anchored once a Session has a message`.
- The doctrine lock itself is unchanged: a Session keeps one doctrine for its whole life, so the system prompt prefix stays stable and the KV and prompt caches survive later configuration edits.
- Headless `talos exec`, the ACP endpoint, and child Sessions are unaffected. A child Session keeps inheriting its parent's doctrine.
- Classic remains the default skin.

## Known limits

The verification gates and the focused tests were run with `TALOS_NEUTRAL_RUNTIME` unset, which is the CI condition. A shell that exports `TALOS_NEUTRAL_RUNTIME=1` makes the `mcode-tools` wrapper exit on purpose and suppresses managed login, so `test:artifact` and the account-related unit files fail there. That is an environment condition, not a defect in this release.

The Windows profile does not cover capabilities, status-contract, smoke, BYOK, policy, sandbox, or release-package, and this release does not claim live-model or cross-platform acceptance beyond the gates listed above.
